# 珞珈书桥开发交接

更新于2026-11-02。本轮 AI 维护者完成本机演示集成，按“可运行功能”和“待接入资源”验收。

## 已实现

- React/TypeScript/Vite 前端与 FastAPI/SQLAlchemy 后端。
- 用户、会话、个人资料、联系方式权限，四个学生与一个管理员的演示账号。
- 书籍发布、图片内容校验、最多三张、列表封面、详情、搜索和分类。
- 我的发布、完整资料编辑、上下架，交易中记录保护。
- 买卖双方预约管理、接受、拒绝、取消、待接受预约过期清理。
- 双方确认完成、重复确认幂等、已完成交易参与者校验。
- 一方已确认后禁止取消，通过争议交给管理员核实。
- 举报、我的反馈、管理员处理与审计日志接口。
- 同一端口提供网页/API，独立本地演示数据、启动前备份与恢复指南。
- SQLite 并发预约及并发双确认测试，真实 API 浏览器主流程测试。

## 当前限制

- 演示登录是受控的无密码账号选择，学校 SSO 和正式生产认证尚未接入。
- AI任务持久化、异步状态与人工确认已实现。视觉模型适配器通过模拟服务验证，真实模型效果需Key和样例验收，默认仍使用清楚标注的模拟模式。
- PostgreSQL 配置保留，但真实 PostgreSQL 容器、并发和部署恢复验收待有 Docker 环境执行。
- SQLite 演示事务串行化，适用于本地少量数据演示，尚未做大规模负载测试。
- 预约过期采用按需清理，尚未部署定时任务。
- 地图路线、正式公益捐赠审核、课程关联与语义匹配未完成。免费赠书分类复用普通预约流程。
- 浏览器测试使用同一电脑的独立会话，多台物理设备的 Wi-Fi 互通、防火墙与睡眠设置需现场验收。
- API 为兼容旧客户端保留 price（元）与 detail 字段，同时新增 priceCents 和统一错误字段。部分旧列表接口仍返回数组，新接入时需按 OpenAPI 合同处理。

## 你接下来负责

1. 运行本机演示，按 [演示指南](LOCAL_DEMO.md) 使用不同账号走完整流程。
2. 确认比赛的日期、现场网络和必须展示的AI能力。
3. 提供真实教材图片、版本信息、公共交接点和品牌素材。
4. 如果比赛需要真实识别，确定可用模型服务及API资源。敏感Key放本机环境配置。
5. 与队友一起完成手机实际访问和演示验收。

## 队友接下来负责

1. 先克隆最新仓库，阅读本文件、AGENTS.md、CONTRIBUTING.md和docs/api/openapi.yaml，运行已有测试，避免重新实现已完成模块。
2. 首个独立任务建议为PostgreSQL验收，分支 `test/api-postgres-concurrency`。在真实PostgreSQL执行迁移、并发预约、同时双确认、备份恢复，并记录结果。
3. 拿到模型资源后创建 `test/ai-image-provider`，配置已有兼容适配器，使用真实教材图片验收字段准确率、结构化输出和失败兜底。不同厂商协议可在现有适配位置扩展。
4. 学校认证和地图/公益模块按比赛要求排期，先定接口与验收规则，再做实现。
5. 数据库变更新增迁移。公共接口变更先更新合同，在PR中说明对前端的影响。

## 合作规则

日常从develop创建单功能分支，后端与部署由队友负责，前端和演示交互由项目负责人及当前AI维护者负责。每次提交前查看git status，PR写明API/迁移/环境变量变化和验证结果。不要提交真实联系方式、密钥、上传图片、数据库、备份、构建产物。

本轮集成覆盖前后端、本机启动与测试。新增迁移e4b8c2039a17与f7c924a6de10，新增Pillow运行依赖。新增ALLOW_LEGACY_HEADERS配置，默认false，另新增AI_PROVIDER/AI_BASE_URL/AI_MODEL/AI_API_KEY配置，默认mock。本机启动选择SQLite作为小规模演示选项，正式数据库基线仍为PostgreSQL。
