```bash
git clone https://github.com/myp-2007/luojia-bookbridge.git
cd luojia-bookbridge
git switch develop
```

稳定分支禁止直接开发。每项工作从 `develop` 创建一个独立分支，完成后提交 PR，再合并回 `develop`。

## 你需要负责的事情

你是项目负责人、仓库所有者和前端/验收负责人。当前优先事项如下：

1. 克隆最新 `main` 或切换到 `develop`，启动前端并走一遍浏览、发布、预约、取消、举报流程。
2. 确认比赛必须展示的主流程，以及是否必须使用真实 AI 识别。
3. 提供书籍图片和教材信息样例，最好包含不同版本、品相和有笔记的书。
4. 提供校内公共交接点清单、项目 Logo、配色和需要展示的学校信息。
5. 如果需要线上演示，提供服务器、域名、HTTPS 和备案要求；如果只现场演示，先准备一台安装 Docker Desktop 的电脑。
6. 对队友提交的前端或后端 PR 做功能验收，重点检查手机端演示和 API 主流程。
7. 及时决定是否接入学校认证、OCR/大模型服务，以及这些服务的测试账号或 API Key。

你不需要手工修改数据库迁移或直接修改 `main`。发现问题时开 Issue 或修复分支即可。

## 队友需要负责的事情

队友是后端、数据、AI 和部署负责人，建议按以下顺序开发：

1. **认证与用户**：建立用户模型、开发登录/会话适配器，移除对任意请求头身份的依赖，并补充普通用户和管理员权限测试。
2. **交易完善**：补充预约过期、争议、卖家预约列表、联系方式授权和并发预约测试。
3. **AI 能力**：建立 `ai_tasks` 表和 queued/running/succeeded/failed 状态，接入可替换的 OCR/模型 Provider，保留 MockProvider 作为无 Key 时的演示方案。
4. **管理后台**：补充书籍审核队列、举报处理、操作日志和管理员接口。
5. **部署验收**：补充 Caddy、备份脚本、生产环境变量、日志方案，并使用真实 PostgreSQL 执行迁移和主流程测试。
6. **接口维护**：先更新 `docs/api/openapi.yaml`，再实现接口；所有数据库变化使用新的 Alembic migration，不修改已经合并的旧迁移。

队友不需要重复实现前端页面。需要前端配合时，在 PR 中写清楚接口字段、状态枚举、错误码和验收步骤。

## 双方交付规则

- 一个分支只做一个功能，命名为 `feat/...`、`fix/...` 或 `chore/...`。
- 开始前先执行 `git status`，确认工作区干净。
- 后端接口先更新合同，前端再联调；前端可以先使用 Mock 数据。
- PR 必须说明修改目录、API/数据库变化、测试命令、已知限制和需要对方配合的事项。
- 合并前至少运行后端测试、前端构建和前端 lint。
- 不提交 `.env`、API Key、数据库文件、上传图片和构建产物。
- 发现接口或迁移冲突时保留双方事实，先解决合同，再解决调用方。
